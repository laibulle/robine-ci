# Supported platforms, defaults, and limitations

The MVP server supports Ubuntu Server 24.04 and 26.04 LTS on x86-64 or ARM64, Erlang/OTP 29, Elixir 1.20, Docker Engine 29.x, Docker Compose v2, and PostgreSQL 17 or 18. The verified CLI binary target is GNU/Linux x86-64 with Erlang/OTP 29 and Docker Engine 29.x. Native remote execution is also verified on Apple Silicon macOS 26 with Erlang/OTP 29 and Elixir 1.20. Its escript ships with target-native Exile files, so release files from different OS/architecture builds are never interchangeable. Other Unix source builds remain best-effort; Windows is unsupported because the native process runtime uses Unix primitives.

Defaults are 2 vCPU, 4 GiB RAM, 512 processes, 20-minute job timeout, 60-second attempt lease, 20-second heartbeat, five-second cancellation grace, and global/repository concurrency controlled by operator configuration. Runner admission stops below 2 GiB free or above 95% filesystem use. Logs retain for 30 days. Logical storage quotas are 50 GiB per instance and 10 GiB per repository; artifact/cache expiry is declared by the workflow and unreferenced blobs have a one-hour GC grace.

Only explicitly trusted GitHub.com repositories connected through a GitHub App are currently supported. The current platform has local and outbound-only remote Docker runners, attempt-private service containers, administrator-owned runner labels, static fleets with optional provider-neutral autoscaling, local or S3-compatible blob storage, bounded matrices and conditions, exact-SHA manual launches, durable UTC schedules, bounded same-revision reusable workflows, YAML schema v1, one OIDC provider, global roles, and no repository-specific ACLs. It does not support untrusted forks, micro-VM isolation, other source-control providers, cross-repository or mutable reusable-workflow references, reusable secret inputs, per-schedule time zones or inputs, Bitbucket/Azure DevOps, deployment environments, approvals, SAML/LDAP/SCIM, or managed-cloud operation.

The server release sets `RELEASE_DISTRIBUTION=none`; do not override it. Robine exposes HTTP/HTTPS through the configured reverse proxy and never requires EPMD, a distributed node name, or an Erlang cookie.

Log search covers only the bounded visible window and raw download is deferred. Docker image tags are allowed but mutable; use digests for reproducibility. Root images remain allowed for trusted code with dropped capabilities and `no-new-privileges`. An unavailable optional GitHub or OIDC integration degrades administrator health but does not make the durable control plane unready.
